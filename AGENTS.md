# Scaff

- Para projeto novo, leia `contexto/PROJETO.md` e use `scaff-iniciar`. Para retomar, leia `contexto/HANDOFF.md`, rode `git status --short` e abra a spec ativa indicada no handoff.
- Use apenas a skill e a seção do playbook relevantes. Consulte `playbook/licoes-de-producao.md` em mudanças de banco, permissões, integrações e publicação, e `playbook/seguranca.md` antes do primeiro deploy em produção. Antes de instalar skill, plugin ou MCP de terceiros, ou de publicar um repositório, siga `playbook/varreduras.md`. Não declare nada pronto sem a evidência pedida em `playbook/revisao.md`. Para conduzir o projeto com a equipe de agentes `scaff-*`, use `scaff-orquestrar` e `playbook/equipe.md`, que indica a skill de cada fase. Para camadas de SaaS (contas, pagamentos, admin, lançamento), use `playbook/saas/`. Para escolher onde publicar (VPS, Cloudflare, Vercel + Supabase, lojas), use `playbook/publicacao/`. Para ferramentas e referências externas, consulte `catalogo/repositorios.md` por busca e, antes de instalar, rode `python scripts/conferir_versoes.py <nome>` para usar a versão estável mais recente.
- Prefira uma entrega vertical com critérios observáveis. Para correções pequenas, o pedido e uma checagem objetiva podem ser a spec. Para escopo maior, mantenha `specs/<id>/spec.md` e atualize somente o necessário.
- Mantenha regras de negócio junto do domínio. Use interfaces quando houver integração, substituição ou teste que precise delas. Confirme as versões e comandos reais antes de adicionar dependências ou configurar CI.
- Execute verificações no ambiente autorizado. Guarde a revisão, comandos executados, resultados e próximo passo no handoff. Separe staging de produção e confira as dependências existentes antes de publicar ou migrar.
- Para Next.js, leia o guia aplicável da versão instalada em `node_modules/next/dist/docs/` quando disponível. Para outras stacks, consulte a documentação oficial da versão.
